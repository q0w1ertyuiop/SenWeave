# SenWeave · 感织：三分钟演示

演示主题：把带基字段的 SenML 数据变成可独立保存的测量，并让设备在采集进程重启后安全重试。项目讲解人：王正。

## 准备与运行

在仓库根目录使用 README 所列工具链及 Node.js 24 以上运行：

```sh
moon update
moon build cmd/bridge cmd/coapbridge --target js --release
node examples/coap/retry-demo.mjs
```

脚本启动绑定 `127.0.0.1` 的采集器和临时 SQLite 账本，通过真实 UDP 执行四次请求，中途停止并重启采集进程。每一步断言响应和数据库内容，失败时非零退出；完成后关闭进程、连接并清理自己的临时目录。没有外部设备、服务、账号或额外 npm 依赖。

## 四个检查点

| 输出 step | 真实动作 | 响应 | 保存包数 |
| --- | --- | --- | --- |
| `first-commit` | `room-a / batch-1` 第一次提交 | `2.04` | 1 |
| `retry-after-restart` | 重启采集器，接收时刻增加 600 秒，同键原样重试 | `2.04` | 1 |
| `same-key-different-payload` | 保留业务键，把数值偏移从 2.5 改成 3.5 | `4.09` | 1 |
| `different-source` | `room-b` 使用相同批次键，提交独立数据 | `2.04` | 2 |

本地已运行这四步。末行的 `status=passed` 来自运行时断言，不是预先打印的成功样例。测量实际保存为 `sensor:temperature`、数值 `22.5`、时刻 `1792999997`；重试没有按新接收时刻改写旧记录。

## 讲解顺序

**前 40 秒：解释数据为什么不能直接拆。** 输入先设 `bn=sensor:`、`bv=20`，后一条只有 `n=temperature`、`v=2.5`、`t=-3`。这条测量离开原包前必须应用基字段和参考时刻。SenWeave 在 MoonBit 中完成有界解析、展开和独立输出，JSON／CBOR 共用同一套语义。

**接着运行命令，观察四行。** 第一行只有存储提交后才产生业务成功；空 ACK 只说明报文收到。第二行说明 CoAP 交换缓存已随进程退出，但持久化业务键仍能识别重试，原始测量和时间保持不变。第三行阻止客户端用同一个键偷偷替换负载。第四行说明不同来源的批次命名空间互不混用。

**最后说明怎样复用。** MoonBit 根包可供文件工具和设备网关直接消费；CoAP 子包提供纯事件接口，宿主选择数据库或消息队列，并报告存储结果。Node.js／SQLite 只是可替换的运行示例。已经复用 Mooncakes 的 CBOR 与 CoAP 包，代码和测试可以独立查看。

**边界说清楚。** 来源查询不是设备认证；示例只在回环地址运行。幂等依赖账本保留原记录，格式或字节变化会冲突。MQTT、native UDP 宿主、Mooncakes 正式发布尚未完成；本项目没有宣称经过真实硬件掉电或公网压力测试。

实现接口和测试范围见 [业务幂等约定](idempotency.md)、[传输接入](transport.md) 和 [互操作记录](interoperability.md)。
