# JSON 输入约定 · 0.1.0-dev.4

`parse_json(input, limits?)` 接收已解码的 Unicode 字符串，返回类型化原始记录。所有后端使用同一实现。字节输入需由调用方严格按 UTF-8 解码；当前函数不检查原始字节来源。

## 数据与版本

依据 [RFC 8428 §4–5](https://www.rfc-editor.org/rfc/rfc8428.html#section-4) 处理基础字段。顶层必须是对象数组，空数组允许进入。

- `v`、`vs`、`vb`、`vd` 对应 `Numeric(Number)`、`Text(String)`、`Boolean(Bool)`、`Data(Bytes)`，每条测量最多出现一个值字段。`s` 允许没有值字段，也允许与一个值字段共存。
- `0`、`false`、空文本与空二进制数据都是存在的值。显式 `null` 不替代缺失，已知字段类型不匹配时拒绝。
- 仅含基础字段及普通未知扩展的记录可以设置后续上下文，例如 `{"bn":"sensor:"}`；计入 `len()`，不计入 `measurement_count()`。含常规字段的测量需要一个值或 `s`。空对象和只有未知扩展的对象返回 `MissingValue`。
- 测量名称使用当前及此前最近的 `bn` 与该条 `n` 检查拼接语法：非空、ASCII 字母或数字开头，后续字符属于 RFC 定义的集合。全球唯一性由应用的命名方案保证。返回的 `Record` 保留原始名称字段。
- 缺失 `bver` 使用版本 10 语义，显式版本必须在数学上等于 10。`10.0` 和 `1e1` 可接受，`10.0000000000000001` 不会被浮点舍入放行。其他版本返回 `UnsupportedVersion`。
- 原始记录的单位按字符串保留，时间和基准数值尚未应用。调用 `Pack::resolve` 执行展开，见 [展开和输出约定](resolution.md)。单位换算、单位注册表策略与更新周期业务校验由应用处理。

## JSON、数值与二进制值

JSON 语法与 Unicode 标量字符串由标准库处理。转义解码后重复的成员名称会被拒绝，包含未知扩展对象内部的重复键。无效代理转义、NaN／Infinity 和尾随内容会被拒绝。

已知数值字段保留原始文本，并提供 binary64 近似值。`9007199254740993`、`-0`、`1.1000` 可按原文读取；`as_double()` 可能舍入，不提供任意精度十进制运算。已知数值字段拒绝大写指数标记 `E`、溢出为无穷大，以及非零数下溢为零的输入；可表示的 subnormal 值允许进入。

`vd` 接受无填充 base64url。拒绝 `=`、普通 Base64 的 `+`／`/`、空白、非法长度和非零未使用位。解码复用标准库，转换覆盖全部 `-`／`_` 字符。

## 扩展与诊断

普通未知扩展按 [RFC 8428 §4.4](https://www.rfc-editor.org/rfc/rfc8428.html#section-4.4) 忽略，仅保留忽略数量。未知的下划线后缀标签返回 `UnsupportedExtension`。未知扩展值内部的标签不作为 SenML 标签解释。

调用失败时不返回部分数据包。诊断提供稳定的 `ErrorCode`、从零开始的记录索引、字段及固定说明。JSON 语法／重复键诊断透传标准库行列位置，行从 1 开始、列从 0 开始；记录索引可能不可用。超过 128 个 UTF-16 代码单元的字段名称从诊断中省略。说明文本不包含原始测量值。

## 资源上限

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| `max_input_code_units` | 1,048,576 | 构造 JSON 树前检查完整字符串长度 |
| `max_records` | 4,096 | 原始记录数，包含上下文记录 |
| `max_depth` | 32 | 完整 JSON 深度，包含未知扩展值 |
| `max_fields_per_record` | 64 | 记录成员数，包含未知扩展 |
| `max_string_code_units` | 65,536 | 成员名称与已知字符串字段的解码后长度 |
| `max_number_code_units` | 128 | 已知数值字段的原始文本长度 |

配置必须为正数，深度最大 128，数字文本长度最大 1,024。长度按 UTF-16 代码单元计数，表情字符通常占两个单元。这些是接入策略；JSON 树内存由完整输入大小及深度约束，记录和字段数在构造树后检查。

## 当前使用边界

`parse_json` 用于类型化读取与字段校验，其返回记录仍依赖前文上下文。`resolve` 可继续执行基字段和相对时间展开，随后输出独立 JSON／CBOR 测量。`parse_cbor` 进入同一模型，见 [CBOR 约定](cbor-profile.md)。已验证与 Python `cbor2` 的编码交换；外部 SenML 库的语义对照和 Mooncakes 发布尚未完成。
