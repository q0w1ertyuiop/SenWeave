# 展开和输出约定 · 0.1.0-dev.5

网关先展开完整数据包，再筛选、归档或转发测量。依据 [RFC 8428 §4.5–4.6](https://www.rfc-editor.org/rfc/rfc8428.html#section-4.5)，`Pack::resolve` 返回不含基字段、没有相对时间、按时间排列的 `ResolvedPack`。

## 消费流程

在消费包的 `moon.pkg` 中导入 `q0w1ertyuiop/senweave`，源码内使用 `@senweave`：

```moonbit
let raw = @senweave.parse_json(
  "[{\"bn\":\"sensor:\",\"bv\":20},{\"n\":\"temp\",\"v\":2.5,\"t\":-30}]",
)
let readings = raw.resolve(reference_time=1793000000.0)
let selected = readings.filter(record => record.name == "sensor:temp")
let json = selected.to_json_string()
```

输出包含 `n: sensor:temp`、`t: 1792999970`、`v: 22.5`。单条 `ResolvedRecord::to_json_string()` 同样输出数组，保持 `application/senml+json` 的数据包形状。可运行完整例子：`moon run examples/gateway --target js`。

`ResolvedPack` 封装记录数组；`record(index)` 对负数和越界返回 `None`。`filter` 按时间顺序对每条测量调用一次谓词，返回新的包。公开记录只读，原始包可以用不同接收时刻再次展开，不会被覆盖。

## 基字段与测量类型

- 每个基字段独立继承，作用于所在记录及之后的记录，直到同一个基字段被替换。`bn` 变化不会重置 `bt`、`bu`、`bv` 或 `bs`。
- `bn` 与该条 `n` 拼接；`n` 缺失视为空串。单位优先取该条 `u`，否则继承 `bu`。空字符串是显式值，不作为缺失处理。
- 数值测量应用 `bv + v`。只有 `s` 的测量若有 `bv`，展开为该基值；没有基值则保留测量值缺失。文本、布尔和二进制测量保持原类型，不把数值基字段加到它们上面。
- `bs` 与 `s` 任一存在时，将缺失一项视为零相加；两者均缺失时不产生 `s`。`0` 会替换此前的非零基值或基和。
- 只有基字段的上下文记录用于更新状态，不产生测量。其他记录需要有一个值字段或显式 `s`。
- `ut` 按原值保留，不与 `bt` 相加。单位换算、接收时间精度、更新周期合理性和设备标识全球唯一性由应用决定。

## 时间与顺序

先计算 `bt + t`，缺失字段按零处理，再判断总和：小于 `268435456` 为相对秒数，大于等于该值为绝对 POSIX 秒数。相对时间加到调用方提供的 `reference_time` 上；核心不读取时钟、不猜测接收时间。

绝对时间包不需要参考时刻。相对时间缺少参考时刻返回 `MissingReferenceTime`；显式参考时刻必须有限且不小于 `268435456`，否则返回 `InvalidReferenceTime`。如果展开后时间低于该阈值，返回 `UnrepresentableTime`，避免输出被接收方再次解释为相对时间。

结果按 binary64 时间值升序排列，相同时间保留输入顺序。`source_index` 是展开前的原始记录索引，包含上下文记录在内，从零开始；诊断也使用原始索引。单条记录输出不携带该本地追溯字段，重新解析后的索引重新计算。

## 数字和失败行为

原始 `Number::json_literal()` 保留十进制原文；`as_double()` 可能舍入。实际加法以 binary64 执行，不保证任意精度十进制结果，例如 `0.1 + 0.2` 可能显示为 `0.30000000000000004`。时间分类和排序也使用 binary64 近似值，极接近阈值或互相接近的大数可能舍入到同一值。

没有加法或加零时保留原始数字文本，避免把 `9007199254740993` 或 `-0` 无故改写。实际加法的结果重新生成有限 JSON 数字文本。任何非有限结果返回 `ArithmeticOverflow`，错误包含原始记录索引和 `v`、`s` 或 `t`，不回显测量值。所有失败都不返回部分结果，也不改变原始包。

## 展开上限和输出范围

`max_expanded_code_units` 默认 `4194304`，必须为正数。展开前缀可能让短输入变大；因此在拼接名称前，用 Int64 累计完整输出的保守上界，包括继承名称／单位、数字文本、base64url、JSON 最坏字符串转义和结构开销。超限返回 `ExpansionLimit`。上界允许提前拒绝实际序列化体积尚未到上限的包；空包需要至少 2 个单元。

此参数约束最终 JSON 的 UTF-16 单元上界，不是所有临时对象或整个进程的内存配额。筛选后的包仍受原展开预算约束。展开后的全名与完整 JSON 可能超过默认解析器的单字段／输入上限，接收方应按应用预算设置相应 `ParseLimits`，不能假定压缩输入和展开输出具有相同大小。

输出移除全部基字段，包括默认版本的 `bver`；四种值保留对应类型，JSON 二进制值重新编码为无填充 base64url。普通未知扩展在解析时已丢弃，`ignored_extension_count` 仅供消费方检查，不序列化。输出不保留扩展，也不作为数字规范化签名格式。`to_cbor_bytes()` 可输出相同测量的原生 CBOR 表示，数字与资源边界见 [CBOR 约定](cbor-profile.md)。
