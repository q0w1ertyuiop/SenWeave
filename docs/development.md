# 开发记录

## 2026-10-26：先确定协议边界

用户场景是设备网关解算测量记录后再筛选、保存或转换表示。RFC 8428 §4.6 明确要求记录离开原数据包前先应用基准字段，这成为项目的核心工作。

检索 Mooncakes 官方模块清单、站内 SenML／RFC 8428 搜索及 GitHub MoonBit 仓库与代码，未找到同范围公开实现；唯一源码匹配是 MIME 类型登记。这个结论限于已检索公开资料，不涵盖未公开或尚未索引的项目。CBOR 编解码与 MQTT／CoAP 传输已有生态包，后续应复用并验证接口。

## 2026-10-26：从标准标签表开始

先实现 RFC 8428 §6 Table 4 的 15 个标签，给后续 JSON 与 CBOR 解析器建立同一套名称。负数 CBOR 键对应基准字段，常规字段使用非负整数；数字字符串不自动转换为整数键。

保留未知名称的识别结果，不在标签查找层决定扩展是否合法。扩展名、强制理解标记和版本政策需要完整数据包上下文，后续放在解析与校验层处理。

本次只建立标签词汇表、公共接口、消费示例和 CI。数据包解析、语义解算、转换、跨语言互操作以及注册表发布都需要后续实现和证据。

## 2026-10-26：从标签表推进到实际 JSON 记录

这一批完成类型化读取与字段校验。§5.1.7 使用只有 `bn` 的上下文记录，统一要求每个对象有值会拒绝这个用法。因此区分原始记录数与测量数，保留上下文记录，也保留 `false`、零、空文本和空二进制值。

JSON 语法、重复键检测和数字文本保留复用标准库。包内数组由 `Pack` 封装，消费方按索引读取。数值保留原始字面量，避免大整数在读取时只剩已舍入的浮点数；版本号另按十进制文本检查数学值，阻止接近 10 的数值被舍入放行。完整算术解算尚未实现。

第一轮 JS 测试暴露 URL 安全 Base64 转换只替换一次的问题，含多个 `-`／`_` 的合法样本被拒绝；改为全量替换后通过，并保留回归样本。测试还覆盖填充、普通字母表、空白和末尾非零未使用位。

本地三个后端均通过 21 个测试，JSON 消费示例输出一致，全目标严格编译通过。扩展、上限、版本 10 约定和未解算范围已单独记录，避免将解析完成等同于安全拆分或转码完成。最后补充的诊断检查覆盖转义后的强制标签识别和超长字段名省略。

## 2026-10-26：让筛选后的网关记录可以独立使用

上一批提交的远端 main 与本地一致，六项 CI 均通过。本批把原始包推进到完整测量：基字段按原顺序应用，之后才按时间排序和筛选。参考时刻由调用方显式提供；绝对时间包无需时钟。时间判定遵循先相加、后比较 `2**28`，避免把绝对基时间与负偏移分别解释。

实现时保留了缺失与零的区别：空前缀、空单位、零基值和零基和能替换前文；基和存在时，即使当前没有 `s` 也输出继承后的和。`bv` 只作用于数值通道，不覆盖布尔、文本或二进制值。仅有基字段的上下文记录仍不当作测量。

展开后的完整名称可能反复复制同一长前缀，因此增加独立的输出预算，在分配拼接字符串前累计保守体积。排序接口在当前标准库中不稳定，比较器加入原始索引作为等时记录的次序，三个后端行为一致。实际数值加法采用 binary64、拒绝溢出；加零和无需加法的数值保留原文。文档明确这一精度边界，没有宣称任意精度计算。

新增网关消费例子：4 条原始记录经过展开与筛选输出 2 条温度记录，并分别独立重读。三个后端各通过 35 个测试，其中新增 14 个测试覆盖基字段重置、时间阈值、时钟缺失、溢出、同时间排序、转义、独立重读、筛选及展开预算。外部 SenML 库的完整互操作对照和 CBOR 集成仍留待后续验证。

## 2026-10-26：接入 CBOR，让两个表示共用语义

上一批的远端提交与本地一致，Windows／Linux 六项 CI 均通过。本批从 Mooncakes 注册表取得 `2515050242/cbor@0.1.2`，读取其解码器与整数、浮点、字节串接口后接入，没有复制底层编解码源码。依赖会保留映射条目，便于检查重复标签；但通用解码入口没有提前限制深度，长度还会转为机器索引，因此 SenWeave 先做独立字节预检。

预检在调用依赖前处理输入大小、嵌套、记录／字段数量和声明长度。只接收确定长度项，避免预检与通用解码器对不定长结构产生不同解释。共享原始记录校验负责版本、名称、互斥值和扩展；CBOR 层另外检查整数键及原生字节串，防止把 JSON 文本标签或 base64 字符串直接当作 CBOR 字段。

数值策略先保住可表示的普通 64 位整数字面量，其余编码使用 binary64 投影。输入 Tag 4 使用标准数字解析器转换，不自行实现十进制浮点算法。负整数下界和最短参数编码限制来自所选依赖，单独写入输入约定。它们也有拒绝测试，不以更换错误文字掩盖边界。

三个后端各通过 54 个测试。为了覆盖自读自写之外的交换，增加 Python `cbor2==5.7.1` 对照脚本：读取 MoonBit 原始／展开输出，再把 Python 生成的 6 条原始记录传入 MoonBit，核对布尔、字节、中文和表情、Tag 4、最大 UInt64 及展开结果。三个后端均通过，CI 增加独立 JS 对照任务。MQTT／CoAP 传输和外部 SenML 库的完整语义对照仍需后续完成。

首次远端检查在解析新增依赖时失败：工具链安装不会初始化 Mooncakes 注册表，而本地已有索引。随后在核心和互操作两个任务中加入 `moon update`，源码运行说明同步增加该步骤。互操作脚本也改为显示底层命令的标准错误，避免依赖或编译失败只留下返回码。

## 2026-10-26：用现有 CoAP 包接收实际测量

本批开始时确认上一批提交已在远端 main，9 项 CI 均通过。读取 Mooncakes 注册表及已发布源码后，选择先接入 MoonCoAP `0.1.1` 的无 I/O 协议核心，宿主使用 Node.js UDP。这样在三个后端都能检查协议与语义逻辑，同时用实际报文验证网络边界。MQTT 包依赖 native 网络栈，此批没有把未运行的 MQTT 集成写成已完成能力。

先增加共用 `parse_payload`，在解码前检查字节数，严格处理 JSON UTF-8，并区分 SenML 有限包与 SenSML 流。普通扩展按标准可忽略，但采集器默认拒绝丢弃，避免设备收到成功响应却失去未处理字段。CoAP 子包不读系统时钟，单调毫秒交给交换生命周期，POSIX 接收秒交给 SenML 展开，两种时间各有校验。

第一轮路由测试没有收到预期错误 ACK。查明依赖的 `Response::error` 参数使用完整报文代码，而不是错误详情数字，改为对应的 132／133／143／128 后通过。保留路径、方法、格式拒绝和完整 ACK 身份的测试，避免只检验内部事件却漏掉线上响应。

去重由 MoonCoAP 的有界端点提供；测试核对相同对端重传只输出一次测量、重发同一 ACK，以及不同对端同 MID 和过期后复用。成功事件代表解析、展开和响应构造通过，当前没有存储后确认接口；这一限制写入公开文档，后续持久化消费不能直接把 ACK 当作落盘凭证。

独立 aiocoap `0.4.14` 客户端已经通过本机 UDP 的 7 次请求，收到两包预期测量和五个拒绝响应；Node 测试另核对自制报文与 ACK 字节、重传、拒绝和有限运行时间。CI 纳入相同的 UDP 与外部客户端检查。网络示例只绑定回环地址，不引入外部服务和额外 npm 依赖。

## 2026-10-26：把成功响应放到宿主存储之后

上一批明确记录了成功应答先于持久化的缺口。本批保留原来的校验即应答模式，增加 `deferred=true`：通过解析后先输出待处理测量，宿主报告存储提交成功才调度 `2.04`，失败调度 `5.00`。没有把某个数据库写进公共 MoonBit 接口，消费方可以用自己的数据库或事务队列实现存储。

读取 MoonCoAP 已发布源码后确认其支持空 ACK、独立确认型响应及客户端控制报文。原入口只接请求，新入口改为通用 `receive`，否则独立响应的客户端 ACK 无法停止重传。句柄绑定采集器，避免两个实例相同数字 ID 被误用；16 项待处理和 30 秒期限限制宿主拖延产生的状态，过期和重复完成不产生成功响应。

Node 示例新增可选的 SQLite 账本，用内置模块和参数绑定保存完整测量文本。测试在收到成功响应后用另一连接读到准确的大整数，实际锁定数据库则收到 `5.00` 且没有新行，解除锁定后的新请求成功。账本可重开，其他应用数据库在打开检查后字节不变，行配额用满时不增加记录。进程退出恰好发生在提交与回包之间的业务重试仍需持久化标识，没有将传输去重扩大为跨重启幂等。

首次 Python 存储对照已通过协议断言，却在 Windows 清理临时文件时失败：SQLite 连接的上下文管理器只管理事务，不关闭连接。改为显式 `closing` 后，协议检查和脚本清理一并通过。独立 aiocoap 现分别在默认模式和存储模式执行 7 次交换，存储模式另外核对已提交内容；相同脚本已加入 CI。

## 2026-10-26：让应用在采集进程重启后原样重试

上一批明确保留跨重启业务幂等的缺口。本批使用应用来源与业务键，不改 SenML 标签，也不把 CoAP MID 当成永久身份。键只在显式启用的延迟路由中接收；不完整、重复或未知查询立即拒绝。公共句柄把原始负载、格式和身份交给宿主，`complete` 区分首次保存、已保存、键冲突和存储失败，旧布尔 `finish` 保留兼容。

最先考虑用展开后的 JSON 比较请求，但相对时间会随接收时刻变化，使同一个重试被误当作新数据。因此持久化原始字节与格式，保留第一次展开结果。SQLite 在写事务中查询与插入，配合唯一索引；原样重试不改时间，同键换负载返回 `4.09`。配额已满时先识别已存请求，避免把成功提交后的重试误报为容量失败。

第一轮过期测试收到的是前一独立响应的重传，而不是新请求的超时响应。原因是测试未确认前一个响应，MoonCoAP 按 NSTART 限制排队。将独立场景隔离后测试通过，实际 UDP 客户端也在返回前完成 ACK 发送；没有修改依赖的拥塞控制行为。

Node 测试运行了采集器重启、来源隔离、负载冲突、满额重试和两个进程共享账本。旧示例账本仅在自有 application ID 下升级；用列名冲突触发失败，核对新增列和版本一起回滚。aiocoap 存储流程扩展为 11 次交换，验证应用查询通过外部协议栈传输，最终只读回 3 包。

展示脚本在真实 UDP 上执行首次提交、重启后重试、同键冲突和不同来源四步，并在每步查询账本。演示说明和矢量图与这些断言对应，不把预期数值写成性能结果。来源认证、键保留期和按字节比较的边界单独说明；SQLite 仍是宿主示例，公共 MoonBit 包不依赖它。

## 2026-10-27：从仓库测试推进到独立分发消费

本批开始确认上一提交远端 9 项 CI 全部通过。已有 CLI 桥接收和返回字符串，适合扩展为可编程 SDK：核心继续负责语义，宿主只做字节边界和参数检查。JSON 输出保留文本，避免 SDK 返回普通对象时提前舍入大整数。CBOR 接收实际 `Uint8Array`，包括有偏移的视图；相对时钟仍显式传入。

类型声明最初考虑泛型默认输出，但仅指定泛型而不提供 `to` 会让类型与运行时默认 JSON 不一致。改为显式 CBOR 重载、默认 JSON 重载和可缩小的动态格式联合类型；独立消费项目使用严格类型检查核对正确推导与预期错误。

读取当前工具的打包行为和模块文档后，为源码归档加入清晰的目录清单，并检查真实 ZIP；没有把 Git 仓库本地忽略规则当作分发保证。首次内容检查误匹配了检查脚本自己保存的路径规则字符串，将规则拆分构造后，完整检查通过，规则本身仍保留。

Node SDK 压缩包在独立临时应用中离线安装，运行时不依赖开发工具链。MoonBit ZIP 解压后与一个新消费模块组成临时工作区，从公开 API 验证数字、CBOR 和 CoAP 延迟完成。两个检查都使用实际归档内容，保留产物和完整性信息；公开注册表安装仍待后续验证。

编译 SDK 会包含 stdlib 与 CBOR 实现，因此构建脚本同时复制实际依赖的 LICENSE 和 NOTICE。新增两平台分发 CI，覆盖运行消费、TypeScript 声明和三个后端的源码归档消费，原有语义和真实 UDP 测试继续保留。

最终回归中，共享账本测试偶发未满足“首轮至少一个成功”的断言。存储配置为零等待，既有合约允许锁竞争失败；独立双进程探测的 30 轮均观察到一次提交和一次 SQLite 锁失败。测试改为直接核对并发响应属于成功或存储失败、首轮账本至多一行，再要求两个采集器顺序重试都成功且最终仅一行，覆盖去重安全和失败后的恢复，而不要求未约定的首轮进展。

## 2026-10-27：按应用收紧预算与诊断输出 · 0.1.0-dev.10

SDK 原有固定上限适合通用调用，但网关可能只接受 8 KiB、16 条记录。新增八项可收紧的单次调用预算，由 MoonBit 桥接映射到现有解析、展开和编码接口；字节限额在解码前检查，展开限额覆盖完整原始包，之后才筛选。JSON 输出按实际 UTF-8 字节检查，CBOR 保留编码前的保守成本检查。预算不能超过 SDK 默认上限，调用之间不共享设置。

复现严格扩展输入时发现，旧 SDK 在展开后才检查扩展丢弃，可能先返回缺失时钟或算术溢出。现在通过共用字节入口在展开前执行扩展准入。选项只读取自身的数据属性，拒绝访问器并忽略原型上的设置，避免继承属性改变格式或配额。

另一个复现显示，未知强制扩展名会原样进入诊断的 `field`，重复键也会带出应用成员名称。它们可能包含业务元数据，因此核心改为只保留标准 SenML 标签，错误类别和可用位置仍保留。三个后端逐个运行示例时，JSON 示例曾因强制取出已省略的 `field` 而退出，随后改为展示稳定错误码；消费方应按可选字段处理诊断位置。

新增测试覆盖预算边界、JSON 多字节输出、空 JSON／CBOR 的不同字节长度、扩展检查顺序、选项属性和未知名称脱敏。测试夹具区分原始包与展开包：基字段上下文会使原始记录数多于独立输出记录数。npm 独立消费验证新增运行预算和类型检查，MoonBit 归档消费新增公开诊断检查。演示文档同时改为直接描述断言和实际测试范围，保留开发决策与修正记录。

## 2026-10-27：设备侧发送与受控丢包 · 0.1.0-dev.11

上一版本的 Windows UDP 检查曾出现一次响应超时，重跑通过，本地 50 轮未复现。此次使用受控对端丢弃首个请求，确认旧示例只发送一次后超时；另用相同 MID／Token 的请求码报文复现了错误接受响应。这两项缺口可以确定，但尚不能据此认定它们就是此前 CI 超时的根因。

发送适配器复用 MoonCoAP Endpoint 的请求状态机，保留单个活动上传和有界历史。SenML 原文在发送前校验，重传保留全部字节；接收方仍负责按实际接收时间展开相对测量。主机提供时钟、随机种子和套接字，公共 MoonBit Sender 可在三个后端消费。空 ACK、最终响应、取消及超时分别报告，业务失败响应不会转换成成功。

Node 宿主替换了手写报文编码与响应判断。首次接桥时发现可选 Double 的导出值带有编译器包装，直接参与 JavaScript 减法触发 NaN 定时器警告；截止时刻改为普通数值与缺失哨兵，构造结果放入不由宿主解构的会话，避免依赖 Option 的具体表示。宿主按协议截止时刻调度，不压缩默认重传间隔，并支持 AbortSignal。

检查取消时序时发现，先 poll 再 cancel 会在重传恰好到期时产生待发送报文。改为先取消活动交换，再处理历史状态，明确测试返回事件不含重传。另测 MID 历史达到上限后拒绝、交换生存期结束后恢复，以及重复独立响应只重发 ACK。

真实 UDP 检查主动丢失请求和成功回复，核对再次发送的字节一致、恢复成功、采集器只验收一次。补充无效响应、错误来源／Token、空 ACK 后超时、发送前取消及在途取消。Node 错误保留实际发送次数和是否收到空 ACK，便于后续定位网络超时；取消原因不进入错误文本。长期处理重复响应需要持续托管 Sender，单次回环宿主在应答后关闭套接字，这一范围已写入接口说明。
