# 开发记录

## 2026-10-26：先确定协议边界

用户场景是设备网关解算测量记录后再筛选、保存或转换表示。RFC 8428 §4.6 明确要求记录离开原数据包前先应用基准字段，这成为项目的核心工作。

检索 Mooncakes 官方模块清单、站内 SenML／RFC 8428 搜索及 GitHub MoonBit 仓库与代码，未找到同范围公开实现；唯一源码匹配是 MIME 类型登记。这个结论限于已检索公开资料，不涵盖未公开或尚未索引的项目。CBOR 编解码与 MQTT／CoAP 传输已有生态包，后续应复用并验证接口。

## 2026-10-26：从标准标签表开始

先实现 RFC 8428 §6 Table 4 的 15 个标签，给后续 JSON 与 CBOR 解析器建立同一套名称。负数 CBOR 键对应基准字段，常规字段使用非负整数；数字字符串不自动转换为整数键。

保留未知名称的识别结果，不在标签查找层决定扩展是否合法。扩展名、强制理解标记和版本政策需要完整数据包上下文，后续放在解析与校验层处理。

本次只建立标签词汇表、公共接口、消费示例和 CI。数据包解析、语义解算、转换、跨语言互操作以及注册表发布都需要后续实现和证据。

## 2026-10-26：从标签表推进到实际 JSON 记录

这一批完成类型化读取与字段校验。§5.1.7 使用只有 `bn` 的上下文记录，统一要求每个对象有值会拒绝这个用法。因此区分原始记录数与测量数，保留上下文记录，也保留 `false`、零、空文本和空二进制值。

JSON 语法、重复键检测和数字文本保留复用标准库。包内数组由 `Pack` 封装，消费方按索引读取。数值保留原始字面量，避免大整数在读取时只剩已舍入的浮点数；版本号另按十进制文本检查数学值，阻止接近 10 的数值被舍入放行。完整算术解算尚未实现。

第一轮 JS 测试暴露 URL 安全 Base64 转换只替换一次的问题，含多个 `-`／`_` 的合法样本被拒绝；改为全量替换后通过，并保留回归样本。测试还覆盖填充、普通字母表、空白和末尾非零未使用位。

本地三个后端均通过 21 个测试，JSON 消费示例输出一致，全目标严格编译通过。扩展、上限、版本 10 约定和未解算范围已单独记录，避免将解析完成等同于安全拆分或转码完成。最后补充的诊断检查覆盖转义后的强制标签识别和超长字段名省略。

## 2026-10-26：让筛选后的网关记录可以独立使用

上一批提交的远端 main 与本地一致，六项 CI 均通过。本批把原始包推进到完整测量：基字段按原顺序应用，之后才按时间排序和筛选。参考时刻由调用方显式提供；绝对时间包无需时钟。时间判定遵循先相加、后比较 `2**28`，避免把绝对基时间与负偏移分别解释。

实现时保留了缺失与零的区别：空前缀、空单位、零基值和零基和能替换前文；基和存在时，即使当前没有 `s` 也输出继承后的和。`bv` 只作用于数值通道，不覆盖布尔、文本或二进制值。仅有基字段的上下文记录仍不当作测量。

展开后的完整名称可能反复复制同一长前缀，因此增加独立的输出预算，在分配拼接字符串前累计保守体积。排序接口在当前标准库中不稳定，比较器加入原始索引作为等时记录的次序，三个后端行为一致。实际数值加法采用 binary64、拒绝溢出；加零和无需加法的数值保留原文。文档明确这一精度边界，没有宣称任意精度计算。

新增网关消费例子：4 条原始记录经过展开与筛选输出 2 条温度记录，并分别独立重读。三个后端各通过 35 个测试，其中新增 14 个测试覆盖基字段重置、时间阈值、时钟缺失、溢出、同时间排序、转义、独立重读、筛选及展开预算。外部 SenML 库的完整互操作对照和 CBOR 集成仍留待后续验证。

## 2026-10-26：接入 CBOR，让两个表示共用语义

上一批的远端提交与本地一致，Windows／Linux 六项 CI 均通过。本批从 Mooncakes 注册表取得 `2515050242/cbor@0.1.2`，读取其解码器与整数、浮点、字节串接口后接入，没有复制底层编解码源码。依赖会保留映射条目，便于检查重复标签；但通用解码入口没有提前限制深度，长度还会转为机器索引，因此 SenWeave 先做独立字节预检。

预检在调用依赖前处理输入大小、嵌套、记录／字段数量和声明长度。只接收确定长度项，避免预检与通用解码器对不定长结构产生不同解释。共享原始记录校验负责版本、名称、互斥值和扩展；CBOR 层另外检查整数键及原生字节串，防止把 JSON 文本标签或 base64 字符串直接当作 CBOR 字段。

数值策略先保住可表示的普通 64 位整数字面量，其余编码使用 binary64 投影。输入 Tag 4 使用标准数字解析器转换，不自行实现十进制浮点算法。负整数下界和最短参数编码限制来自所选依赖，单独写入输入约定。它们也有拒绝测试，不以更换错误文字掩盖边界。

三个后端各通过 54 个测试。为了覆盖自读自写之外的交换，增加 Python `cbor2==5.7.1` 对照脚本：读取 MoonBit 原始／展开输出，再把 Python 生成的 6 条原始记录传入 MoonBit，核对布尔、字节、中文和表情、Tag 4、最大 UInt64 及展开结果。三个后端均通过，CI 增加独立 JS 对照任务。MQTT／CoAP 传输和外部 SenML 库的完整语义对照仍需后续完成。

首次远端检查在解析新增依赖时失败：工具链安装不会初始化 Mooncakes 注册表，而本地已有索引。随后在核心和互操作两个任务中加入 `moon update`，源码运行说明同步增加该步骤。互操作脚本也改为显示底层命令的标准错误，避免依赖或编译失败只留下返回码。

## 2026-10-26：把库接到文件检查和外部 SenML 数据

本批开始时确认上一批远端 main 与本地一致，7 项 CI 通过。离线工作流采用 Node.js 处理文件、UTF-8、标准流和输出文件，MoonBit 处理解析、展开、筛选和序列化。两个边界只交换字符串，序列化后的 JSON 内容不经过宿主数字解析，大整数能够原样写出。

`check` 最初就执行完整展开，避免语法通过却仍存在基值溢出或缺失参考时刻。输出文件先写同目录临时文件，再用独占硬链接发布；已有文件、输入文件或并发创建的目标都不会被替换。未知普通扩展的丢弃会提示，也可用严格参数拒绝。文件和管道读取均计数，防止只做文件大小预检后漏掉读取期间增长的输入。

编译器提示主程序包的黑盒测试方式将变更，于是将可测行为移到 `internal/inspector`，桥入口只导出字符串函数。三个后端各通过 58 项测试；CLI 新增独立端到端检查，覆盖路径、编码、字节流、文件保护和并发写入。

固定安装 KPN SenML `1.0.1` 后，实际内容与仓库 master 有差别。数值／布尔的双向 JSON、CBOR 及 JSON 基准和共 5 条流程通过；另外复现了旧 CBOR 基准和键、Python 3 文本构造和输入时刻元数据的三处差异。测试保留这些边界，SenWeave 的标准标签不为旧实现改写。该版本的反向输入测试只统计实际测量值更新，完整互操作范围另文记录。
