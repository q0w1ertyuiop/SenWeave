# 开发记录

## 2026-10-26：先确定协议边界

用户场景是设备网关解算测量记录后再筛选、保存或转换表示。RFC 8428 §4.6 明确要求记录离开原数据包前先应用基准字段，这成为项目的核心工作。

检索 Mooncakes 官方模块清单、站内 SenML／RFC 8428 搜索及 GitHub MoonBit 仓库与代码，未找到同范围公开实现；唯一源码匹配是 MIME 类型登记。这个结论限于已检索公开资料，不涵盖未公开或尚未索引的项目。CBOR 编解码与 MQTT／CoAP 传输已有生态包，后续应复用并验证接口。

## 2026-10-26：从标准标签表开始

先实现 RFC 8428 §6 Table 4 的 15 个标签，给后续 JSON 与 CBOR 解析器建立同一套名称。负数 CBOR 键对应基准字段，常规字段使用非负整数；数字字符串不自动转换为整数键。

保留未知名称的识别结果，不在标签查找层决定扩展是否合法。扩展名、强制理解标记和版本政策需要完整数据包上下文，后续放在解析与校验层处理。

本次只建立标签词汇表、公共接口、消费示例和 CI。数据包解析、语义解算、转换、跨语言互操作以及注册表发布都需要后续实现和证据。

## 2026-10-26：本地验证

`moon check --target all --deny-warn` 通过；`moon test` 的 native、JS、wasm-gc 三个目标各通过 2 个测试，消费示例在三个目标输出一致。测试覆盖 Table 4 全部 15 个标签，以及未知名称、大小写、空白、数字字符串和整数边界。`moon fmt --check` 通过，公共接口由 `moon info` 生成。

第一次严格检查发现派生 trait 方法的隐式提升已弃用，因此显式声明了 Eq 和 Debug 方法扩展。这个修改由编译器诊断触发，验证后保留。

## 2026-10-26：修正首次 CI 的工具链差异

首次远端 CI 在格式检查阶段失败：2026-10-23 工具链将两个公共签名中的 `Int` 格式化为 `Int32`，本地旧工具链尚未采用这一命名。随后在独立目录安装与 CI 一致的工具链、更新代码及生成接口，并重新通过三个目标的测试与示例、全目标严格检查和格式检查。

README 记录实际工具链要求；CI 的 Node.js 配套 action 更新为 v6。初始接口差异由这一轮实际 CI 反馈发现，不影响标签编号或查找语义。

## 2026-10-26：从标签表推进到实际 JSON 记录

这一批完成类型化读取与字段校验。§5.1.7 使用只有 `bn` 的上下文记录，统一要求每个对象有值会拒绝这个用法。因此区分原始记录数与测量数，保留上下文记录，也保留 `false`、零、空文本和空二进制值。

JSON 语法、重复键检测和数字文本保留复用标准库。包内数组由 `Pack` 封装，消费方按索引读取。数值保留原始字面量，避免大整数在读取时只剩已舍入的浮点数；版本号另按十进制文本检查数学值，阻止接近 10 的数值被舍入放行。完整算术解算尚未实现。

第一轮 JS 测试暴露 URL 安全 Base64 转换只替换一次的问题，含多个 `-`／`_` 的合法样本被拒绝；改为全量替换后通过，并保留回归样本。测试还覆盖填充、普通字母表、空白和末尾非零未使用位。

本地三个后端均通过 21 个测试，JSON 消费示例输出一致，全目标严格编译通过。扩展、上限、版本 10 约定和未解算范围已单独记录，避免将解析完成等同于安全拆分或转码完成。最后补充的诊断检查覆盖转义后的强制标签识别和超长字段名省略。
