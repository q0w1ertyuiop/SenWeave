# 业务幂等约定 · 0.1.0-dev.8

设备没有收到成功响应时，可能在采集进程重启后再次发送同一批数据。CoAP 的对端／MID 去重只覆盖当前交换生命周期；应用需要另一份可持久化的请求身份，才能识别跨重启重试。

## 可复用接口

`Collector::new(deferred=true, idempotency=true)` 在默认 `POST /ingest` 上启用可选应用查询：

```text
/ingest?source=room-a&key=batch-1
```

`source` 和 `key` 必须同时出现，各 1–64 个 ASCII 字母、数字、`.`、`_`、`-`，不修剪或改写大小写。顺序不限，重复、额外、空值和不完整参数返回 `4.00`。读取的是协议层已解码的 Uri-Query 文本，不再次做 URL 解码；本约定不接受包含百分号的字面值。`BusinessKey::from_queries()` 可独立验证同一约定，错误只返回 `Err(())`。无查询参数继续表示无业务键；默认构造器仍拒绝所有查询。

`Pending` 中的 `Delivery` 提供 `business_key()`、`payload()`、`format()`。宿主在自己的存储事务中判定结果，然后调用 `complete(outcome, monotonic_ms)`：

| 宿主结果 | 条件 | 响应与事件 |
| --- | --- | --- |
| `Stored` | 新请求已提交 | `2.04`、`Completed` |
| `AlreadyStored` | 同来源、同键、同格式、同原始字节已存在 | `2.04`、`Duplicate` |
| `KeyConflict` | 同来源、同键已存在，但格式或原始字节不同 | `4.09`、`Conflict` |
| `Failed` | 无法完成事务 | `5.00`、`StorageFailed` |

这些结果均由宿主判定，MoonBit 接口不检查外部事务。无业务键不能报告 `AlreadyStored` 或 `KeyConflict`；句柄仍受 30 秒期限、单次完成和时钟规则约束。旧 `finish(stored~, monotonic_ms)` 对应 `Stored`／`Failed`，保持已有调用方式。

`source` 是应用命名空间，不能直接当作已认证设备身份。回环示例允许客户端填写它；部署到设备网络时，宿主必须从认证会话或可信网关映射得到来源，检查查询来源是否一致，再执行存储。当前示例未实现这层认证。

## SQLite 宿主如何判定

示例账本保存原始负载 BLOB、格式编号、来源、业务键和首次展开后的 JSON。唯一索引约束 `(source, business_key)`；`BEGIN IMMEDIATE` 内先查已存请求，再比较或插入，最后提交。两个采集进程共享同一账本时，一个事务持有写锁；竞争失败返回 `5.00`，后续重试可以识别已提交数据。不会先在进程内查询再单独写入。

重复判定比较实际字节，不用散列碰撞假设，也不将解析后的 JSON 当作身份。空格、数字拼写、JSON／CBOR 格式发生变化都算不同负载；即使测量数值等价，也会返回冲突。客户端对同一业务键应原样重发第一次请求。

这对相对时间尤其有用：第一次在 `1793000000` 接收 `t=-3`，保存 `1792999997`；重启后在 `1793000600` 接收相同负载，返回已存成功并保留第一次测量，不新增 `1793000597`。第一次无业务键写入的旧记录不能自动恢复历史键，仍保留为无键行。

旧账本版本 1 在单个事务中升级到版本 2：新增四列和唯一索引，保留测量，成功后才推进版本；测试注入列冲突，确认先前 ALTER 操作和版本一起回滚。这里只维护本项目示例账本格式，没有通用数据库迁移接口。

查询已存请求发生在新增配额检查之前，账本 4096 行用满后，相同请求仍返回成功。新键超额失败，已有数据不被逐出。身份保留期等于账本记录保留期；删除账本或手动清理记录后不能继续依靠这些键去重。业务应用需要明确备份、归档和键复用策略。

## 已运行的场景

MoonBit 测试覆盖身份解析、显式启用、原始字节传递、四种结果、重复完成和过期。Node 测试通过真实 UDP 检查重启后重试、首次时间保留、大整数文本、来源隔离、冲突、满额重试、共享账本并发和旧格式升级／回滚。aiocoap 独立客户端也验证带查询的成功、重复、冲突和缺失来源。

```sh
moon build cmd/bridge cmd/coapbridge --target js --release
node --test tests/cli.test.mjs tests/coap.test.mjs
node examples/coap/retry-demo.mjs
```

这是一套明确的业务请求身份与宿主事务约定，不提供网络、数据库和设备三方的分布式事务；确认响应丢失时，客户端需要携带同一个键继续重试。
